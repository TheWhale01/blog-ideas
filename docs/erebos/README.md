# Erebos — Server Configuration Documentation

**Erebos** (`Ἔρεβος`) is the name of my NixOS server configuration. In Greek mythology it is the primordial personification of **darkness** / **deep shadow** (the underworld). It runs every service in my home lab: a self-hosted media stack, identity provider, file sync, monitoring, and a personal blog.

This directory is the **official documentation** of the [`TheWhale01/erebos`](https://github.com/TheWhale01/erebos) repository. It is generated from the live NixOS flake and kept in sync so the code and the docs never drift.

## Overview

This repository defines a **reproducible, fully declarative** NixOS server (`erebos`) plus a mirrored `stage` environment. Everything—system packages, services, containers, disk layout, secrets, home directory, and even the blog-builder site definition—is declared in Nix. A single `nixos-rebuild switch` deploys the entire host.

Key design choices:

- **Flakes + NixOS modules** for reproducibility.
- **agenix** for encrypted secrets (age-encrypted, decrypted at build time into `/run/agenix/`).
- **disko** for declarative disk partitioning and filesystems.
- **terranix + OpenTofu** to keep the infrastructure-as-code layer (Authentik, Grafana, Nextcloud, etc.) in sync with the NixOS config.
- **Podman** for containers (OCI, not Docker), with the `podman` overlay backend.
- **Traefik 2** as the single reverse proxy / entry point, with automatic Let's Encrypt certificates via Cloudflare DNS challenge.
- **Authentik** as the central OIDC/SAML identity provider, protecting most ingress services.
- **Monitoring**: Prometheus + Grafana + Loki + Promtail.

## Environments

Two environments are defined, mirroring a production and a staging host:

| Flake output | Host name | Purpose |
|---|---|---|
| `nixosConfigurations.erebos` | `erebos` (prod) | Production server |
| `nixosConfigurations.erebos-stage` | `erebos-stage` | Staging server |

Environment-specific behavior is driven by the `env` arg passed to the module system, so e.g. hostnames, domains, ports, and secret sets differ between prod and stage. The `sys/vars.nix` file is the **single source of truth** for ports and per-service settings.

## Core Concepts

### NixOS Flake

`flake.nix` is the entry point. It pins all inputs (nixpkgs, home-manager, agenix, disko, blog-builder, cleanerr, nixos-modules, terranix) and produces two `nixosConfigurations` plus two "apply" apps.

Key parts:

- `pkgs` is built with `allowUnfree = true` and `permittedInsecurePackages = [ "immich-2.7.5" ]` (Immich requires a proprietary binary).
- `erebosConfig` builds the NixOS system with modules including home-manager, agenix, disko, blog-builder, cleanerr, and the custom `modules.nixosModules.system`.
- `terranixState` builds the terranix config that generates `config.tf.json` for OpenTofu.
- Apps `apply` and `apply-stage` run `tofu apply` using the generated `config.tf.json`.

### Home Manager (user `hades`)

Home Manager is wired in as a NixOS module. The user `hades` gets:

- **Zsh** as the default shell.
- **direnv** with `nix-direnv` integration.
- A curated set of system packages (`vim`, `git`, `nixd`, `nil`, `basedpyright`, `ruff`, `typescript-language-server`, `fastfetch`, `ripgrep`, `tree`, `nvtopPackages.nvidia`, `pciutils`, `unzip`, `tmux`, `jq`, `mailutils`, `dig`, `wget`, `podman-compose`, `nodejs`, `id3v2`, `flac`, `file`, `irssi`, `openssl`, `bitwarden-cli`, `agenix`, `bridge-utils`).
- **SSH authorized keys** for several machines (hades, pontos, strategos, etc.), managed declaratively.

The full user config lives in `sys/home-manager/`.

### Encrypted Secrets (agenix)

Secrets are stored as **`*.age`** files under `secrets/` and mapped one-to-one in `sys/secrets.nix`. agenix decrypts them at build time into `/run/agenix/<name>`, which modules then reference via `config.age.secrets.<name>.path`.

Secret categories:

| Category | Examples |
|---|---|
| Service credentials | `nextcloud`, `nextcloud`, `vaultwarden`, `grafana`, `immich`, `authentik` |
| Shared configs | `slskd`, `transmission`, `hades`, `traefik`, `gluetun`, `grafana-secret` |
| Matrix | `matrix`, `mas`, `matrix-appservice`, `erebot`, `livekit`, `alertmanager-webhook` |
| Terraform | `authentik`, `grafana`, `jellyfin` (Terraform provider credentials) |
| Email / SMTP | `authentik-smtp` |

> ⚠️ `secrets/` is **not** committed in plaintext. `.age` files are age-encrypted and the decryption keys are provided out-of-band (e.g. at deploy time). `secrets.nix` only maps file paths.

### Disk Layout (disko)

`sys/disko/` contains declarative disk partitions.

**Prod (`prod.nix`):**

- `disk /dev/vda`: GPT, 512 MB EFI system partition (`/boot`, vfat) + btrfs root on remaining space.
- `data /dev/mapper/whale--nas-data`: LVM volume group, ext4 on `/data` with `noatime`.

Prod also ships an initrd post-device command (`lvm vgchange -ay`) so the LVM data volume is activated at boot.

**Stage (`stage.nix`):**

- `disk /dev/sda`: GPT, 512 MB ESP + btrfs root on remaining. No LVM/data volume defined.

### Terraform / OpenTofu (terranix)

Terranix translates NixOS modules into Terraform JSON (`config.tf.json`), which OpenTofu then applies against the target provider(s) to manage the lifecycle of cloud-native or API-backed resources—notably:

- Authentik (identity provider, applications, users, policies, outposts).
- Grafana (admin users, provisioning).
- Nextcloud, Immich, Jellyfin, etc. (application-level resources).

The `apps.<system>.{apply,apply-stage}` flake apps:

```bash
nix run .#apply          # prod
nix run .#apply-stage    # stage
```

## Containers Overview

Containers are declared with the NixOS `virtualisation.oci-containers` module (Podman). Each file under `sys/containers/` defines one or more containers.

| File | Container(s) | Notes |
|---|---|---|
| `default.nix` | *(imports the rest)* | Global Podman settings: overlay storage, `dockerCompat`, auto-prune, `DOCKER_HOST` env wrapper, an upgrader "update-containers" service |
| `nextcloud.nix` | `nextcloud`, `nextcloud-office` | Nextcloud on `8881`, Collabora code on `9980` (no TLS; Traefik terminates) |
| `authentik.nix` | `authentik`, `authentik-worker`, `authentik-ldap`, `authentik-proxy` | Multi-process Authentik; LDAP port `3389`; SMTP via `authentik-smtp.age` |
| `transmission.nix` | `transmission`, `flood`, `transmission-port-sync` | Transmission via `gluetun` network (`--network=container:gluetun`); flood dashboard; auto port-sync on VPN port change |
| `gluetun.nix` | `gluetun` | WireGuard (ProtonVPN, Switzerland); forward ports to Transmission; `--cap-add NET_ADMIN/RAW`, tun device |
| `lidarr.nix` | `lidarr` | Audio metadata/handling, Authentik auth |
| `maintainerr.nix` | `maintainerr` | "The Perfect Media Janitor" |
| `openbooks.nix` | `openbooks` | Ebook search/download |
| `actualbudget.nix` | `actualbudget`, `enableactual` | Budget app + enableactual UI, Authentik proxy |
| `aurral.nix` | `aurral` | RSS podcast manager |
| `slskd.nix` | `slskd` | *(defined in `sys/services/slskd.nix`)* |
| `homepage.nix` | *(dashboard)* | *(defined in `sys/services/homepage.nix`)* |

Note: `sys/services/slskd.nix` is the systemd service (slskd daemon), while `sys/containers/slskd.nix` does **not** exist (the file name matches a container name in the list but was not found).

## Getting Started

### Prerequisites

- Nix with flakes enabled (`experimental-features = nix-command flakes` in `/etc/nix/nix.conf`).
- NixOS installed on the target machine.
- `agenix` private keys available (decrypts `*.age` files at build/decrypt time).

### Rebuild the target

```bash
# Prod
sudo nixos-rebuild switch --flake .#erebos

# Stage
sudo nixos-rebuild switch --flake .#erebos-stage
```

### Test / build without switching

```bash
sudo nixos-rebuild test --flake .#erebos
sudo nixos-rebuild build --flake .#erebos
```

### Update dependencies

```bash
nix flake update
sudo nixos-rebuild switch --flake .#erebos
```

### Apply Terraform/OpenTofu

```bash
nix run .#apply          # prod
nix run .#apply-stage    # stage
```

### Format and check

```bash
nix fmt
nix flake check
```

## Roadmap / TODOs

From `Erebos.md` in the vault:

- **Monitoring** — Grafana + Prometheus deployed, but no alerting running and a poor log analyzer. Proper alerting (Grafana Alert / or similar) needs configuring.
- **Backups** — no robust backup solution in place yet.
- **Auto Podman image updates** — `update-containers` service exists but could be more robust (image signatures, panic-less restart, policy).
- Container/layout cleanup — there are a few legacy/empty files (e.g. `sys/services/jellyfin/default.nix`, `get_m3u.py` auxiliary) that may be deprecated later.
